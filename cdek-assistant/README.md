# Закрытый помощник оператора СДЭК

Работающий локальный прототип: сервер, вход с ролями, SQLite/FTS5, поиск по допущенным источникам, проверка материалов администратором, журнал решений и история версий. Интерфейс на русском, адаптирован для работы во время звонка.

**К рабочим консультациям база пока не допущена.** В текущей базе нет одобренных источников. Без источников сервер не вызывает модель и сообщает об ограничении. Без настроенного OpenAI API сервер не выдаёт заготовленные ответы за ИИ.

## Запуск

Нужны Python 3.12+ с SQLite FTS5 и современный браузер. Сторонние Python-пакеты, npm-установка, сборка, база данных как отдельный сервис и CDN не требуются. Node/Playwright/Chromium нужны только для браузерной проверки; в данной облачной среде они уже установлены.

Используйте существующий checkout `/workspace/Test_Master`. Каждая облачная задача уже изолирована: не создавайте Git worktree без прямого запроса пользователя.

```bash
cd /workspace/Test_Master/cdek-assistant
python3 manage.py import /workspace/cdek-private/materials
python3 manage.py addendum /workspace/cdek-private/packaging-addendum
python3 manage.py user administrator --role admin
python3 manage.py user operator --role operator
python3 manage.py serve --dev --port 8080
```

Команда `user` запрашивает пароль скрыто через терминал, не принимает его в аргументах и требует не менее 12 символов. Повторная команда меняет пароль/роль и отзывает существующие сессии. Учётных записей и паролей по умолчанию нет. В основной базе тестовые аккаунты не создавались. Вызовы браузерных тестов создают временные аккаунты только во временной копии базы и удаляют её.

`--data-dir` до подкоманды или `CDEK_DATA_DIR` выбирает закрытое хранилище, по умолчанию `/workspace/cdek-private`. Сохранённые в этой среде архивы уже проверены и распакованы в `materials/` и `packaging-addendum/`. Исходные материалы не добавляются в Git, `web/` или публичные статические файлы.

Сервер слушает только loopback. Для внутреннего развёртывания поставьте аутентифицированное приложение за HTTPS reverse proxy, передавайте исходный Host и задайте точный origin:

```bash
python3 manage.py serve --port 8080 --origin https://assistant.internal.example
```

Это пример домена, не опубликованный адрес. Не используйте `--dev` при развёртывании: он разрешает локальный HTTP и cookie без Secure. В обычном режиме обязательны HTTPS origin и Secure cookie. Конфигурация прокси, TLS, сеть организации, резервное копирование и пользовательский доступ ещё не развёрнуты. Публичный static hosting для этого проекта не подходит.

Для внутренней проверки готовности: GET `/health` должен вернуть `{"status":"ok"}`; GET `/api/coverage` без входа должен вернуть 401. После входа проверьте покрытие, генерацию без допущенных источников, административный поиск и журнал. PID и открытый порт сами по себе не подтверждают готовность.

## OpenAI

В настройках облачной среды сохранены требования:

- `CDEK_MODEL_API_KEY` — секрет для HTTPS-запросов к `api.openai.com`; значение вводится только через настройки среды.
- `CDEK_MODEL` — модель с поддержкой Chat Completions и JSON object output; предложено `gpt-4.1-mini`.
- `CDEK_DATA_DIR` — `/workspace/cdek-private`.

В текущий процесс ключ не поступил. Сохранение черновика не применяет настройки и не публикует среду. После добавления значений и применения конфигурации перезапустите сервер. Не печатайте ключ и не сохраняйте его в `.env`, Git, JS, URL, журнал или инструкции. Используется штатный HTTPS-прокси и проверка TLS. Провайдер получает запрос и допущенные фрагменты; обеспечьте разрешённую организацией обработку внутренних данных перед рабочим использованием.

API вызывается сервером по фиксированному адресу `https://api.openai.com/v1/chat/completions`. Произвольный URL из браузера не принимается. Поиск и вызов модели ограничены размером; одновременно выполняется не более двух запросов. Каждый существенный вывод должен иметь цитату с существующим ID фрагмента. Сервер проверяет точное вхождение цитаты, версию и действующий допуск, в том числе после завершения вызова модели. При ошибке формата, неизвестной цитате или отзыве допуска ответ блокируется.

Проверка вхождения цитаты **не доказывает семантическое следование вывода** и применимость правила. Модель может ошибаться; оператор должен проверять основание, а реальные сценарии нужно испытать с подключённой моделью. Нельзя заявлять, что ИИ уже проверен в рабочих консультациях.

## Материалы, версии и допуск

Основной пакет: 315 файлов из SHA256-манифеста; 204 страницы и 2 XLSX. Дополнение: 11 файлов, две новые версии существующих источников 395 и 1037, 227 строк классификации грузов, 36 таблиц и 282 DOM-блока. Счётчики таблиц/строк не равны числу уникальных правил. Хеши подтверждают согласованность с приложенным манифестом, а не подлинность первоисточника.

Импорт проверяет хеши и выбирает предпочтительные файлы по registry.json. Прошлые и новые редакции не индексируются как независимые действующие документы. Дополнение заменяет текущие фрагменты 395/1037 и сохраняет старые тексты, метаданные, решения и хеши в `source_versions`. Повторный импорт основного пакета не понижает установленное дополнение. Изменение содержимого или метаданных отзывает допуск; исчезнувшие из нового пакета источники исключаются. История видна администратору.

У администратора есть поиск по недопущенным материалам с явной пометкой «не для консультаций». Рабочий поиск доступен оператору только по допущенным и не просроченным источникам. Источник допускается индивидуально с шестью доказательствами: актуальность, полнота, приложения/изображения, область применения, противоречия/приоритеты, запись проверки. Сохраняются проверяющий, время UTC, SHA256 и срок повторной проверки до 90 дней. Отменённые, заменённые и недоступные документы допустить нельзя. Наличие текста или надписи «последняя редакция» не даёт автоматического допуска.

Очередь составлена по backlog.json: частота ссылок определяет исходный порядок, ключевые документы и обязательные схемы вынесены выше. Администратор может зафиксировать релевантность или блокировку с обоснованием. Изменение статуса очереди не меняет допуск. Отсутствующая страница 2662 и отменённый документ 2139 сохранены как ограничения; 2223/2230 не включены в индекс.

XLSX разбираются из оригинального OOXML без выполнения формул. Сохраняются лист, ячейка, кешированное значение, формула, объединения и контекст заголовков. Сверка с приложенным JSON обнаружила пропущенные скрытые листы в обеих книгах; скрытые листы не участвуют в поиске. При расхождениях допуск XLSX блокируется. В книге идентификации обнаружено 137 изображений, которые не интерпретированы. Ячейка B146 для «Духи» пуста/пробельная: класс по названию не выводится.

Для дополнения сохранены категория, груз, характеристики, метод, source_row/source_cell, rowspan/colspan, DOM region и заголовок HTML. Индекс таблицы/строки с нуля — техническая привязка, не номер пункта. 395 и 1037 не объединяются в одно правило; сначала требуется область применения. Наличие груза в таблице упаковки не означает разрешение на перевозку. Пустой `image-text-gaps.json` не доказывает полноту схем; обязательные приложения А–Г требуют проверки.

## Проверки

```bash
cd /workspace/Test_Master/cdek-assistant
python3 -m unittest discover -s tests -v
node tests/browser.cjs
```

22 серверные/импортные проверка: реальный пакет и дополнение, повторяемость, история версий, различия способов упаковки, SHA256, XLSX, пустой класс «духи», роли, CSRF, Origin/Host, сессии, лимит входа, сроки и отзыв допуска, цитаты и блокировка вымышленных ссылок. Браузерная проверка: вход/выход, покрытие, честный отказ без источников, поиск администратора, версии, очередь, журнал, роль оператора, мобильная ширина, отсутствие JS-ошибок.

Сценарии неоднозначного груза, разных объёмов духов, авиа/авто, отсутствующих документов, отменённого/отсутствующего источника и противоречий проверены на уровне защитных механизмов и синтетического адаптера модели. Это не испытания ответов реальной OpenAI и не разрешения на перевозку. Упаковочные сценарии дополнения проверены на уровне импорта и адресации, не как рабочие консультации. Тесты реальных пакетов явно пропускаются, если закрытое хранилище отсутствует; отчёт о пропусках нельзя считать полной проверкой.

## Что осталось

1. Добавить серверный ключ OpenAI, применить настройки и проверить реальные ответы.
2. Выдать учётные записи через `manage.py user`; выбрать внутренний HTTPS-домен и настроить reverse proxy.
3. Обеспечить разрешённый доступ к `base.cdek.ru`. Текущая попытка получила 403 от сетевого прокси; вход в Вики и актуальность первоисточников не проверены.
4. Проверить обязательные приложения, схемы, изображения XLSX, пропущенные листы, применимость 395/1037 и противоречия. Только затем выдавать индивидуальный допуск.
5. Пройти реальные сценарии с цитатами, организовать пересмотр источников и резервное копирование SQLite/закрытых материалов. Автоматического сетевого обновления/обхода всей Вики нет; обновления выполняются повторным импортом проверенного пакета.

База и сайт в целом не объявляются готовыми к рабочим консультациям. Вся Вики не изучена, актуальность всех материалов не подтверждена.
